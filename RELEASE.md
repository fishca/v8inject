Добор остатка после разбора 2026-11-12: закрыты хвост мелочи — изоляция
разделяемой памяти, барьер протокола, экранирование JSON, временные файлы и
ещё несколько мелочей в отрисовке.

## Что нового

- **Разделяемая память изолирована.** Блок `Local\v8inject.<pid>` получает
  собственный дескриптор безопасности: полный доступ только у создавшего его
  пользователя и у SYSTEM. Имя блока предсказуемо, и раньше его мог открыть
  любой процесс сессии — подсунуть свой блок и отвечать вместо payload.
- **Второй хост к тому же 1С получает внятную ошибку.** Блок с уже
  существующим именем считается ошибкой: хост больше не подключается к
  чужому блоку, а сообщает, что с этим процессом уже кто-то работает.
- **Барьер в протоколе.** Слово состояния читается через
  `InterlockedCompareExchange` — это парный acquire-барьер к тому store'у,
  которым хост публикует запрос. Текст запроса теперь гарантированно виден
  payload'у, когда состояние говорит «запрос».
- **JSON в ответах хуков экранируется.** Имя хука (`--name`) и текст ошибки
  больше не ломают ответ: кавычка или обратная косая черта раньше портили
  весь JSON для хоста.
- **Временные файлы — настоящий `%TEMP%`.** Файловый канал команд 8.5
  (для payload'а, загруженного без сессии, через `hookcbt`) указывал на
  `C:\Users\fishca\AppData\Local\Temp` — на чужой машине такого каталога
  нет, и канал не работал нигде, кроме машины автора. Теперь это
  `%TEMP%\v8i_cmd85_req.txt` и `%TEMP%\v8i_cmd85_res.txt`.
- **Отладочные дампы — рядом с логом.** Классы окон, ход подписки на 8.5,
  принятая команда и получатель пишутся в `<папка v8inject.exe>\v8inject.log.*`
  вместо захардкоженного пути.
- **База модуля в отчёте не обрезается.** Она печаталась через `%X` после
  `& 0xFFFFFFFF`, то есть на x64 в JSON попадала половина адреса; теперь
  полные 64 бита.
- **Оверлей меню 1С прячется под диалог комментария.** Диалог ввода
  комментария не увеличивал счётчик модальности, и оверлей главного меню
  оставался поверх диалога — теперь прячется, как под окнами настроек и
  списков.
- **Перо и кисть возвращаются в DC.** Раньше они удалялись, оставаясь
  выбранными в контексте устройства: висячая ручка для всех последующих
  отрисовок.

## Проверено

- Сборка x86/x64 Release без единого предупреждения, ctest — 2/2 на обеих
  архитектурах.
- Живая проверка на платформе 1С не выполнялась — изменения ждут прогона по
  плану из [docs/VERIFY.md](docs/VERIFY.md).
