`v8inject-gui` в оформлении 1С, меню всех действий GitBar, компактный режим и
клонирование репозитория.

## Что нового

- **Окно `v8inject-gui` в стиле 1С.** Палитра снята с живого Конфигуратора
  8.5: кремовая форма, рамки #B0A68E, белые поля, синее выделение, Tahoma
  8 pt. Кнопки, поля и список процессов нарисованы вручную: подсветка при
  наведении, «вдавленное» состояние, синяя рамка у поля в фокусе, бежевая
  шапка списка и компактные строки. Навигация по Tab, диалог настроек — в
  той же теме.
- **`v8inject-gui` запрашивает права администратора.** Без этого инжект в
  процесс 1С, запущенный с повышенными правами, завершался `ACCESS_DENIED`
  (win32=5).
- **Меню всех действий в GitBar.** Лента заканчивается тринадцатой
  ячейкой-многоточием, которая открывает popup-меню со всеми командами;
  то же меню открывается правым щелчком в любом месте панели. Раньше меню
  было доступно только в компактном режиме.
- **Компактный режим.** Если ширина клиентской области окна меньше
  `compactwidth` из ini (по умолчанию 900 px, `0` отключает), панель
  сворачивается в одну ячейку и перестаёт накрывать собственные кнопки
  тулбара Конфигуратора. При расширении окна лента возвращается сама.
- **Клонирование репозитория.** Пункт «Клонировать репозиторий…» в меню:
  URL (по умолчанию подставляется `remote` из ini), выбор пустой папки
  через штатный диалог оболочки, `git clone` с таймаутом 10 минут, запись
  `dumpdir` и `remote` в ini и предложение сразу выгрузить конфигурацию в
  файлы. Сценарий для репозитория, созданного на GitHub с README.
- **Первый push в репозиторий, созданный с README.** Если `origin` уже
  содержит коммиты, push сообщает об отклонении, а панель предлагает слить
  истории (`pull --allow-unrelated-histories`) и повторить push. Ветка
  `origin` (`main`/`master`) определяется через `git ls-remote --symref`,
  а не по имени локальной ветки. Pull до первого push тоже работает: без
  upstream выполняется `pull origin <ветка origin>`.
- **Выгрузка на 8.5 больше не запускается повторно.** Платформа возвращает
  команду 45 только после закрытия модального диалога, поэтому проверка
  «диалог есть» после вызова видела его отсутствие и выгрузка запускалась
  заново. Теперь фоновый поток следит за появлением нового окна платформы,
  пока выполняется команда.

## Проверено

- Сборка x86/x64, `ctest` — 2/2 теста на обеих архитектурах.
- Живой прогон на 8.3.27 (x86) и 8.5.1.1529 (x64): лента 316×24 с
  многоточием, popup-меню, правый щелчок по панели, компактный режим,
  клонирование в пустую папку с записью ini и предложением выгрузки.

## Установка

`v8inject-v0.2.11-x64.zip` / `v8inject-v0.2.11-x86.zip` — `v8inject.exe`,
`v8inject-gui.exe`, `v8inject-agent.exe`, `v8i_payload.dll`.
