# Справочник команд v8inject (CLI)

Полный список команд `v8inject.exe`, включая те, что не вошли в текст
`--help`. Список команд payload — в [ARCHITECTURE.md](ARCHITECTURE.md) §6;
git-панель — [GITBAR.md](GITBAR.md).

---

## 1. Общие правила

- **Выбор процесса.** Любой команде можно указать `--pid <n>` — тогда
  цель определяется точно. Без него берётся первый процесс с заданным именем
  образа (две открытые 1С различаются только по `--pid`).
- **Общие опции** (разбираются хостом, payload не передаются):
  `--dll <path>` (по умолчанию `v8i_payload.dll` рядом с exe), `--timeout <ms>`
  (по умолчанию 15000), `--module <имя>` для реверс-команд.
- Payload выбирается по разрядности **целевого процесса** (1С 8.3 — x86,
  8.5 — x64).
- Ответ payload печатается строкой `reply : {JSON}`; при неудаче — коды
  возврата: 1 — ошибка аргументов, 2 — процесс не найден, 3 — инжект не
  удался, 4 — рукопожатие не удалось, 5 — нет ответа на команду.
- Лог хоста и payload — `v8inject.log` рядом с `v8inject.exe`; консоль
  переводится в UTF-8 (ответы содержат кириллицу).

## 2. Процесс и сессия

| Команда | Что делает |
|---|---|
| `v8inject --help` | краткая справка (не полная — см. этот документ) |
| `modules <exe>` | PID цели, разрядность цели и хоста; без инжекта |
| `inject <exe> [--dll]` | только внедрить DLL, сессию не открывать |
| `probe <exe> [--dll] [--timeout]` | внедрить + открыть сессию + команда `version`; печатает имя сессии и путь к логу |
| `launch <exe> [аргументы 1С…] [--dll]` | запустить 1С и внедрить payload **до создания главного окна**; payload ставит WH_CBT в `v8i_probe` — ранняя подписка на 8.5. Ждёт выход 1С до 8 с |
| `log [--clear]` | напечатать или удалить лог хоста |
| `attach <exe> [--dll]` | интерактивная сессия (ниже) |
| `hookcbt [секунд=300]` | глобальный WH_CBT с `hMod = payload`: Windows сама загрузит payload в цель при создании её первого окна. Хост крутит message pump и через N секунд снимает хук |

### Сессия `attach`

```bat
v8inject attach 1cv8.exe
```

Одна сессия — много команд: **хуки живут, пока сессия не завершена**, это
главное отличие от одноразовых команд. Ввод — по строке на команду:

- `exit` / `quit` — выход;
- `sleep <ms>` — пауза выполняется **хостом** (полезно, чтобы подождать,
  пока цель вызовет хук);
- прочие строки — дословно в payload с таймаутом 120 с.

В сессии доступны все команды payload, включая не форвардимые CLI:
`cmd <num> [sub]`, `menu [filter]`, `menucmd <hwnd> <id>`, `str <addr>`.

## 3. Реверс-инжиниринг (форвард в payload)

| Команда | Пример | Что делает |
|---|---|---|
| `scan <exe> <addr>` | `scan 1cv8.exe 0x1A2B3C4D --module 1cv8.exe` | разбор COM-объекта по адресу через ITypeInfo (memid, oVft, cParams, имена методов) |
| `objects <exe>` | | окна процесса: класс, заголовок, `GWLP_USERDATA` |
| `pe <exe> [module]` | | PE-заголовок, секции, экспорты модуля из памяти |
| `peek <exe> <addr> [len=64]` | | дамп памяти; парсит адрес без `0x` и с ним |
| `find <exe> <pattern> [--module m] [--wide] [--max N]` | | поиск строки/байт в памяти; `--wide` — UTF-16LE; таймаут 120 с |
| `disasm <exe> [<addr>] [--module m]` | | дизассемблер Capstone; без адреса — от начала .text |
| `around <exe> <addr> [--count N]` | | инструкции вокруг адреса с маркером |
| `xref <exe> <addr\|имп-имя> [--from A --to B] [--count N]` | | кросс-ссылки на адрес или импорт; таймаут 120 с |
| `imports <exe> <module> [filter]` | | импорты модуля |
| `exports <exe> <module> [filter]` | | экспорты модуля из памяти |
| `mods <exe> [filter] [--count N]` | | список загруженных модулей |
| `memmap <exe> [--count N]` | | карта committed-регионов |
| `heapobjects <exe> [--module m] [--count N]` | | живые объекты кучи по vtable |
| `findvalue <exe> <hex> [--count N] [--module m]` | | все 4-байтные вхождения значения |
| `byhwnd <exe> <hwnd> [--offset 0x200]` | | объект-владелец окна |

## 4. Хуки

```bat
v8inject hook   1cv8.exe <addr|module!Export|module+0xRVA> [--name text]
v8inject hooks  1cv8.exe
v8inject unhook 1cv8.exe <id|all>
v8inject trace  1cv8.exe [--count N] [--since N] [--clear]
```

- Цель хука: адрес (`0x619E9F70`), экспорт модуля (`core83.dll!findMethod`) или
  RVA (`core83.dll+0x39F70`). Имена движка манглированы, поэтому экспорт
  ищется точным совпадением, затем без регистра, затем **подстрокой**. Если
  подстрока подходит к нескольким экспортам, хук не ставится — в ответе
  перечислены кандидаты с RVA.
- `trace --since N` выдаёт записи с номером больше N (основа для `watch`).
- Одноразовые команды ставят хук и снимают его при выходе; для наблюдения —
  `attach`.

Механика хуков — [ARCHITECTURE.md](ARCHITECTURE.md) §7.

## 5. Команды 1С

| Команда | Доступ | Что делает |
|---|---|---|
| `cmd <num> [sub]` | **только в `attach`** | команда дизайнера на 8.3 (выгрузка в файлы — 45, открыть конфигурацию — 2) |
| `cmd85 <num> [sub]` | `v8inject cmd85 …` или в `attach` | команда дизайнера на 8.5 (таймаут 120 с: cmd 45 открывает модальный диалог выгрузки — «UI thread did not answer» в ответе и есть успех) |
| `cmdinfo` | CLI / attach | диагностика: как найти command receiver на данной платформе |
| `frames` | CLI / attach | что прислал `eventCreateFrame`, статистика CBT |
| `exports85 <module> [--count N]` | CLI / attach | экспорты модуля **с диска** (в памяти 8.5 занулены) |
| `gitbar [hide]` | CLI / attach / GUI | показать/скрыть git-панель |
| `menu` / `menucmd` / `str` | **только в `attach`** | меню фрейма / вызов пункта / чтение UTF-16 строки |

> Ограничение: `v8inject cmd 1cv8.exe 2` сейчас печатает usage и выходит
> (команда не зарегистрирована в CLI-диспетчере) — пользуйтесь
> `attach` с командой `cmd 2`. Находка A3 в [AUDIT.md](AUDIT.md).

## 6. Автоматизация: `watch`

Триггер «1С выгрузила конфигурацию в файлы» для git-конвейера:

```bat
v8inject watch 1cv8.exe --dump-dir E:\dump\config --run "git add -A && git commit -m auto"
    [--debounce-sec N] [--timeout-sec N] [--once] [--dry-run]
```

Как работает:

1. Снимает хвосты прошлой сессии (`unhook all`), ставит inline-хук на
   `kernel32.dll!CreateFileW --name cfw`.
2. Каждые 250 мс опрашивает `trace --since <seq>`; пути файлов декодирует
   командой `str <addr>` и кэширует.
3. Когда всплеск обращений к файлам под `--dump-dir` затихает на
   `--debounce-sec` (по умолчанию 8 с) — запускает `--run` через
   `cmd.exe /S /C`, ожидание команды до 180 с.
4. Без `--once` перевзводится и продолжает следить; глобальный таймаут — 600 с.
5. `--dry-run` печатает, что сделала бы.

## 7. GUI (`v8inject-gui.exe`)

Оконный дубликат основной функциональности: список процессов с фильтром
(процессы session 0 скрыты), выбор payload-DLL с авто-подстановкой по
разрядности цели, «Инжектировать» / «Отключиться», командная строка для
произвольных команд payload (кубан: `objects | pe | peek <addr> [len] |
scan <addr>`) и живой лог. Кнопки GitBar: показать / скрыть / Настройки —
диалог пишет `%APPDATA%\v8inject\gitbar.ini`. Двойной клик по строке списка =
«Инжектировать».

## 8. Агент (`v8inject-agent.exe`)

Трей-программа «в духе стартера Снегопата»: раз в 2 с ищет новые процессы
`1cv8.exe`/`1cv8c.exe`/`1cv8s.exe` и внедряет в них payload (один раз на PID),
опционально сразу показывая GitBar. Настройки — `%APPDATA%\v8inject\agent.ini`,
автозапуск — `HKCU\...\Run\v8inject-agent`, лог —
`%APPDATA%\v8inject\agent.log`. Запуск с `--settings` сразу открывает диалог
настроек. Меню трея: внедрить в запущенные 1С / GitBar: показать /
Автозапуск / Настройки / Выход.
