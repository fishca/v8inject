# План RE: служебный реестр сервисов Конфигуратора

Цель — найти способ получить `ICommandService` из процесса Конфигуратора
для нативного пункта меню «GitBar» (`src/payload/mainmenu.cpp`).

## 1. Что известно (инструментально подтверждено)

| Факт | Как установлено |
|---|---|
| `?current_process@core@@…` возвращает валидный SCOM_Process (vtable в core83.dll, rva 0x3EAB68) | Вызов экспорта на UI-потоке через маршал |
| `getService` (vtable слот 14) на этом объекте возвращает null для IID_ICommandService | 20 ретраев × 60 с, значения в журнале |
| QI(IID_ICommandService) на приёмнике/core/рамке → E_NOINTERFACE | MMStepQI, live прогон |
| Обёртка config.dll+0xCF320 (test rcx / mov rax,[rcx] / lea rdx,[IID] / call [rax+0x70]) перехватывается хуком | HookInstallObserved, IID-лог в журнале |
| Через обёртку проходят ВНУТРЕННИЕ ключи: {00000004-0001-0000-0000000001000000}, {A7CBB6D8-01AF-0000-…} — не классические IID | IID-лог живого прогона |
| config.dll вызывает `call [svc+0xD8]` (vtable слот 27) после getService — получение менеджера | Статический анализ байт вокруг call-сайта 0x1925C8 |
| Слот createByClsid = 5, getService = 14 (подтверждён обёрткой 1cv8+0xBFCB0) | call [rax+0x70] = 0x70/8 |
| Дизассемблировка current_process: TLS-контекст с итерацией — не глобальный синглетон | disasm core83.dll на живом процессе |

## 2. Что не работает (перечёркнутые подходы)

- ~~Перебор слотов 8–24 вызовами~~ — деструктивен: слот 8 (`getCategoryClasses`) пишет по диким указателям из интерпретированного GUID → падение 1С;
- ~~QI на frame/core/receiver~~ — E_NOINTERFACE для ICommandService;
- ~~Хук только 1cv8-обёртки~~ — она не вызывается при работе Конфигуратора.

## 3. Фаза R1: дизассемблировка getService (слот 14)

**Цель**: понять, как SCOM_Process::getService ищет сервис и по какому ключу.

**Инструменты**: payload `disasm` / `peek` на живом процессе (или IDA/x64dbg на core83.dll с диска).

**Шаги**:

1. **Найти реализацию getService.**
   - Вызвать обёртку (`1cv8.exe+0xBFCB0`) — она делает `call [rax+0x70]`.
   - Хук обёртки перехватывает `rcx` (объект) — из него читается vtable.
   - `peek proc → vtable`; `peek vtable + 0x70 → адрес getService impl`.
   - Дизассемблировать impl: `v8inject disasm 1cv8.exe <impl_addr>`.

2. **Понять формат реестра.**
   - В impl искать: обход списка/таблицы, сравнение IID-байтов (mov/psubusb с 8F885821-подобными константами), возврат указателя.
   - Определить: смещение реестра внутри SCOM_Process (поле this + off), размер записи (sizeof service entry), формат ключа (IID? внутренний номер? составной).

3. **Найти регистрацию ICommandService.**
   - В disasm найти, куда добавляются записи (registerService слот 12? отдельный вызов?).
   - Проверить: регистрируется ли ICommandService в Конфигураторе (может, он доступен только через специфический контекст).

**Критерий**: известен путь «адрес реестра → ключ → ICommandService».

## 4. Фаза R2: получение ICommandService

**Варианты по результатам R1**:

- **Реестр в поле SCOM_Process**: читать реестр напрямую из памяти (offset + key), найти запись ICommandService, взять указатель.
- **Внутренний ключ**: конвертировать IID_ICommandService в внутренний ключ (по образцу {00000004-0001-…}) и вызвать getService с ним.
- **Менеджер доступен без ICommandService**: найти менеджер напрямую (глобал в config.dll, поле frame-объекта, heap-скан).

**Критерий**: `svc != null && [svc + 0xD0] != null` в журнале mainmenu.

## 5. Фаза R3: нативный пункт

**После получения менеджера** — построение по рецепту v8snack (уже реализовано в mainmenu.cpp):

1. MMStepTemplates → образцы пунктов
2. MMStepRegister → registerCommands (наша группа)
3. MMStepSource → CommandInterface + addBand + addSource
4. MMStepTraps → перехваты приёмника
5. Перестройки по расписанию v8snack

**Критерий**: «пункт «GitBar» отрисован платформой» в журнале; пункт виден в «Сервисе».

## 6. Фаза R4: проверка и релиз

2. Проверить: QI/getService не вызывают сбоев платформы.

## 7. Известные риски

| Риск | Митигация |
|---|---|
| Раскладка SCOM_Process меняется между билдами | Калибровка по билду (Ф2.1 profiles) |
|getService не экспортируется напрямую | Вызов через vtable слот 14 на захваченном объекте |
| Реестр сервисов защищён (CFG/vtable guard) | Обход через прямое чтение памяти (peek) |
| Нативный пункт нестабилен | Ключ nativemenu=0, оверлей остаётся fallback |
