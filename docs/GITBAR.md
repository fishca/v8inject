# GitBar — git-панель в Конфигураторе

GitBar — панель инструментов, которая живёт **внутри процесса 1С** и даёт
операции git над выгрузкой конфигурации в файлы прямо из Конфигуратора:
коммит, push, история с графом, ветки, stash, теги, статус. Реализация —
`src/payload/gitbar.cpp` (≈2000 строк), публичная точка входа — команда
payload `gitbar [hide]` (`include/v8inject/gitbar.h`).

---

## 1. Как панель попадает в Конфигуратор

```bat
v8inject gitbar 1cv8.exe --pid 12345   # показать (payload остаётся в процессе)
v8inject gitbar hide 1cv8.exe --pid 12345
```

То же — кнопками в `v8inject-gui.exe`, через `v8inject attach`
(команда `gitbar`) или автоматически от `v8inject-agent.exe`.

Панель — **дочернее окно окна Конфигуратора**, пристыкованное справа в ряду
тулбаров, поэтому выглядит как штатный тулбар платформы. Все 12 иконок взяты из
ресурсов самой платформы (`core83_root.res`, `mngcore_root.res`,
`core85_root.res`, `moxel_root.res`, `backend_root.res`), а не нарисованы
заново.

Жизненный цикл (`gitbar.cpp:1920-2017`):

1. Команда `gitbar` → `CreateThread(BarThread)`.
2. `FindFrame` — `EnumWindows` по своему PID, первое видимое окно с непустым
   заголовком.
3. По классу рамки выбирается режим докинга:
   - **8.3** (`V8TopLevelFrame`) — GDI child-окно `WS_CHILD|WS_VISIBLE` внутри
     рамки;
   - **8.5** (`V8Window0*`) — дочернее окно в DWM-клиенте не видно, поэтому
     панель создаётся как top-level owned `WS_POPUP` с
     `WS_EX_TOOLWINDOW|NOACTIVATE|LAYERED`.
4. Создаются два tooltip-контрола: per-cell (подсказка при наведении на каждую
   из 12 кнопок) и отдельный tracking-tip для статусов выполняемых действий;
   ставится таймер 500 мс (переприсоединение при изменении размера рамки),
   запускается поток сообщений.

Ни меню Win32, ни стандартных child-контролов не используется: чужой цикл
сообщений рамки ненадёжен для BUTTON/WM_DRAWITEM — всё рисуется вручную в
`WM_PAINT`, клики хит-тестятся по ячейкам.

## 2. Кнопки (12)

При наведении на кнопку показывается всплывающая подсказка с названием действия
и git-командой; статусы запущенных действий («git pull…», ошибки) выводятся
отдельным tracking-tip под панелью на 3 секунды.

| # | Кнопка | Действие |
|---|---|---|
| 1 | дискета | выгрузка конфигурации в файлы — штатная команда дизайнера 45 (при закрытой конфигурации сначала 2 — открыть) |
| 2 | лист с плюсом | `git init` в папке выгрузки + `remote add origin` из настроек (`remote set-url`, если origin уже есть) |
| 3 | стопка с галочкой | `git add -A` + коммит; комментарий спрашивается каждый раз (значение `commitmsg` из ini — лишь дефолт) |
| 4 | стрелка вверх | `git push`; грязное дерево предлагает закоммитить, при отсутствии upstream — `push -u origin HEAD` |
| 5 | шестерёнка | диалог настроек |
| 6 | часы с карандашом | окно истории: граф + коммиты + патч выбранного коммита |
| 7 | стрелка вниз | `git pull --no-edit`, результат в MessageBox |
| 8 | круговые стрелки | `git fetch --all --prune` |
| 9 | граф веток | `git branch -a`; кнопки «Переключить» (`checkout`) / «Удалить» (`branch -d`) |
| 10 | стопка листов | `git stash list`; «Применить» (`stash pop`) / «Удалить» (`stash drop`) |
| 11 | звезда | `git tag -n1`; «Удалить» (`tag -d`) / «Отправить» (`push origin <tag>`) |
| 12 | документ с галочкой | `git status --porcelain`; «Индексировать» (`add`), «Снять» (`reset HEAD --`), «Отменить» (`checkout --`), «Коммит», «Amend» (`commit --amend --no-edit`) |

## 3. Настройки

`%APPDATA%\v8inject\gitbar.ini`, секция `[git]`:

```ini
[git]
gitpath=C:\Program Files\Git\cmd\git.exe   ; путь к git.exe (по умолчанию — из PATH)
dumpdir=E:\dump\config                     ; папка выгрузки = корень репозитория
commitmsg=                                 ; комментарий по умолчанию (пусто = дата-штамп)
remote=git@github.com:user/repo.git        ; origin для git init (необязательно)
```

Тот же ini пишет диалог настроек GUI и читает payload. Диалог настроек панели —
полностью рисованный (свой карет, Ctrl+V из клипборда), класс `V8iGitBarSettings`.

## 4. Механика запуска git

`RunGit` (`gitbar.cpp:115-178`):

- командная строка `"gitpath" "arg"...`; anonymous pipe с наследуемым концом
  записи (`STARTF_USESTDHANDLES`: stdout и stderr → одна труба),
  `CREATE_NO_WINDOW`;
- неблокирующее чтение `PeekNamedPipe` + `WaitForSingleObject(50 мс)`;
  таймаут **120 с** — зависший git (например, ждущий учётные данные в
  консоли) снимается `TerminateProcess` с пометкой `<timeout>`;
- вывод конвертируется из UTF-8; длинный вывод для тултипов обжимается
  до 160 символов.

**Комментарий к коммиту** передаётся через файл `%TEMP%\v8i_commitmsg.txt`
(UTF-8 без BOM, `git commit -F`), потому что argv-кавычки для кириллического
многострочного текста ненадёжны; фолбэк — `-m`, если файл не записался.

## 5. Окно истории

`ShowGitLog` (класс `V8iGitLog`, 940×660), три зоны:

- **список коммитов** (~45% высоты): колонки Граф / Коммит / Комментарий /
  Дата / Автор; ромб графа и polyline строятся из `git log --graph --decorate
  -n 300 --date=short --pretty=format:%x1f%h%x1f%an <%ae>%x1f%ad%x1f%d%x1f%s`
  (поля разделены 0x1F); граф следует за топологией коммитов, а не за датами;
- **строка деталей**: `git show -s --format=%an <%ae>, %ad%n%B`;
- **панель патча**: `git show --stat --patch --no-color` с раскраской
  +/-/@@.

Навигация: ↑↓ / PageUp / PageDown / Home / End / Enter / Esc; колесо
прокручивает список или дифф. Окно растягивается.

## 6. Геометрия и отрисовка

- ячейка 24×24, панель 12 ячеек, 290×24 (`kCell/kCells/kBarW/kBarH`);
- фон RGB(238,234,222), рамка RGB(176,166,142), подсветка hover/press;
- иконки — 16×16 premultiplied BGRA из `src/payload/icons.h`
  (сгенерирован `tools/gen_icons.py` из PNG, декодер на чистом Python —
  без PIL), рисуются через `AlphaBlend` (msimg32);
- происхождение каждой из 12 иконок зафиксировано в
  `src/payload/icons/SOURCE.json` (файл ресурса 1С + смещение);
- подсказки: 12 per-cell инструментов `TTF_SUBCLASS` (показываются при
  наведении, ширина до 360 px) и отдельный `TTF_TRACK`-инструмент для
  статусов действий; он же снимается таймером 2 через 3 секунды.

## 7. Автоматическая проверка

`tools/check_gitbar.sh [8.3|8.5] [--keep]` — E2E-тест (локально, нужна
установленная платформа):

1. закрыть тестовые `1cv8`;
2. запустить Конфигуратор (`DESIGNER /F <база> /DisableStartupDialogs…`);
   8.3 → `8.3.27.1989` x86 + база `awa_empty`; 8.5 → `8.5.1.1529` x64 + база
   `awa_empty_851`;
3. внедрить: `v8inject gitbar 1cv8.exe --pid <pid>`; в ответе должно быть
   `"status":"ok"`, `"visible":true`;
4. через PowerShell/EnumWindows найти окно класса `V8iGitBar` по PID,
   проверить видимость и ненулевой размер;
5. уборка; exit 0/1.

Скрипт уже поймал реальные регрессии (падение из-за CBT-хука) — прогонять
перед каждым коммитом, затрагивающим payload или панель.
