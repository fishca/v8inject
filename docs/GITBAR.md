# GitBar — git-панель в Конфигураторе

GitBar — панель инструментов, которая живёт **внутри процесса 1С** и даёт
операции git над выгрузкой конфигурации в файлы прямо из Конфигуратора:
коммит, push, история с графом, ветки, stash, теги, статус. Реализация —
`src/payload/gitbar.cpp` (≈2000 строк), публичная точка входа — команда
payload `gitbar [hide]` (`include/v8inject/gitbar.h`).

---

## 1. Как панель попадает в Конфигуратор

```bat
v8inject gitbar 1cv8.exe --pid 12345   # показать (payload остаётся в процессе)
v8inject gitbar hide 1cv8.exe --pid 12345
```

То же — кнопками в `v8inject-gui.exe`, через `v8inject attach`
(команда `gitbar`) или автоматически от `v8inject-agent.exe`.

Панель — **дочернее окно окна Конфигуратора**, пристыкованное справа в ряду
тулбаров, поэтому выглядит как штатный тулбар платформы. Все 12 иконок взяты из
ресурсов самой платформы (`core83_root.res`, `mngcore_root.res`,
`core85_root.res`, `moxel_root.res`, `backend_root.res`), а не нарисованы
заново. Тринадцатая ячейка — нарисованное многоточие: открывает меню со всеми
действиями (там же клонирование репозитория, у которого нет своей иконки).

Жизненный цикл (`gitbar.cpp:1920-2017`):

1. Команда `gitbar` → `CreateThread(BarThread)`.
2. `FindFrame` — `EnumWindows` по своему PID, первое видимое окно с непустым
   заголовком.
3. По классу рамки выбирается режим докинга:
   - **8.3** (`V8TopLevelFrame`) — GDI child-окно `WS_CHILD|WS_VISIBLE` внутри
     рамки;
   - **8.5** (`V8Window0*`) — дочернее окно в DWM-клиенте не видно, поэтому
     панель создаётся как top-level owned `WS_POPUP` с
     `WS_EX_TOOLWINDOW|NOACTIVATE|LAYERED`.
4. Создаются два tooltip-контрола: per-cell (подсказка при наведении на каждую
   из 12 кнопок) и отдельный tracking-tip для статусов выполняемых действий;
   ставится таймер 500 мс (переприсоединение при изменении размера рамки),
   запускается поток сообщений.

Ни меню Win32, ни стандартных child-контролов не используется: чужой цикл
сообщений рамки ненадёжен для BUTTON/WM_DRAWITEM — всё рисуется вручную в
`WM_PAINT`, клики хит-тестятся по ячейкам.

## 2. Кнопки (12)

При наведении на кнопку показывается всплывающая подсказка с названием действия
и git-командой; статусы запущенных действий («git pull…», ошибки) выводятся
отдельным tracking-tip под панелью на 3 секунды.

| # | Кнопка | Действие |
|---|---|---|
| 1 | дискета | выгрузка конфигурации в файлы — штатная команда дизайнера 45 (при закрытой конфигурации сначала 2 — открыть) |
| 2 | лист с плюсом | `git init` в папке выгрузки + `remote add origin` из настроек (`remote set-url`, если origin уже есть) |
| 3 | стопка с галочкой | `git add -A` + коммит; комментарий спрашивается каждый раз (значение `commitmsg` из ini — лишь дефолт) |
| 4 | стрелка вверх | `git push`; грязное дерево предлагает закоммитить, при отсутствии upstream — `push -u origin HEAD`; если удалённый репозиторий уже содержит коммиты (README), предлагает слить истории и повторить |
| 5 | шестерёнка | диалог настроек |
| 6 | часы с карандашом | окно истории: граф + коммиты + патч выбранного коммита |
| 7 | стрелка вниз | `git pull --no-edit`; без upstream — `pull origin <ветка origin>`, при несвязанных историях — с `--allow-unrelated-histories` |
| 8 | круговые стрелки | `git fetch --all --prune` |
| 9 | граф веток | `git branch -a`; кнопки «Переключить» (`checkout`) / «Удалить» (`branch -d`) |
| 10 | стопка листов | `git stash list`; «Применить» (`stash pop`) / «Удалить» (`stash drop`) |
| 11 | звезда | `git tag -n1`; «Удалить» (`tag -d`) / «Отправить» (`push origin <tag>`) |
| 12 | документ с галочкой | `git status --porcelain`; «Индексировать» (`add`), «Снять» (`reset HEAD --`), «Отменить» (`checkout --`), «Коммит», «Amend» (`commit --amend --no-edit`) |
| 13 | многоточие | popup-меню со всеми действиями (включая «Клонировать репозиторий…» и «Выгрузить расширение в файлы (команда 205)»); то же меню открывается правым щелчком по панели |

### Выгрузка расширения конфигурации (команда 205)

В popup-меню рядом с «Выгрузить исходники (команда 45)» есть пункт
«Выгрузить расширение в файлы (команда 205)»: выгрузка выбранного расширения в
папку `dumpdir`, чтобы её можно было положить в отдельный git-репозиторий.

Штатная команда 205 контекстная — платформа решает, что выгружать, по
**активному окну**. Если активно окно «Расширения конфигурации» и в списке выбрано
расширение, открывается диалог «Выгрузить файлы расширения конфигурации -
<расширение>». При любом другом активном окне платформа открывает диалог выгрузки
основной конфигурации, поэтому перед выбором пункта меню нужно открыть
«Расширения конфигурации» и выбрать расширение — панель напоминает об этом
подсказкой при запуске действия.

GitBar страхует от ошибки: watcher распознаёт появившийся диалог по заголовку.
Если вместо диалога расширения показан диалог основной конфигурации, панель
немедленно закрывает его (`WM_CLOSE`) и выводит предупреждение «Выгрузка
расширения отменена: активным было окно конфигурации…». На 8.5 команда 205
возвращает управление только после закрытия модального диалога, поэтому закрытие
выполняет именно watcher, а не ожидание ответа команды.

Как и для команды 45, панель только открывает диалог: путь (по умолчанию
`dumpdir`) и параметры (XML-файлы/архив) проверяет и подтверждает пользователь.

### Первый пуш в непустой репозиторий

Если репозиторий на GitHub создан с README (или любым стартовым коммитом),
локальная выгрузка и `origin` имеют несвязанные истории, и первый `git push`
отклоняется. Панель предлагает слить их (`pull --allow-unrelated-histories`)
и повторить push. Ветка origin при этом берётся из
`git ls-remote --symref origin HEAD` — `main` или `master`, как настроено в
репозитории, а не имя локальной ветки. Кнопка pull до первого push работает
так же: без upstream выполняется `pull origin <ветка origin>`.

### Клонирование репозитория (popup-меню)

Тринадцатое действие живёт только в popup-меню рядом с `git init`:
«Клонировать репозиторий…». Меню открывает ячейка-многоточие в конце ленты
(в компактном режиме она единственная) или правый щелчок в любом месте панели.
Это сценарий «репозиторий на GitHub уже создан (с README/.gitignore), а
конфигурация ещё никуда не выгружалась»:

1. спрашивается URL репозитория; по умолчанию подставляется `remote` из ini;
2. выбор папки через штатный диалог оболочки (можно создать новую кнопкой
   «Создать папку»); непустая папка отклоняется с предложением выбрать другую —
   `git clone` разворачивается только в пустую;
3. `git clone <url> <папка>` (таймаут 10 минут: клон большой выгрузки дольше
   обычных 120 с);
4. при успехе `dumpdir` и `remote` в ini переписываются на новую папку и URL,
   затем панель предлагает сразу выгрузить конфигурацию в файлы (команда 45).

После клонирования первый push — обычный fast-forward, поэтому сливать
несвязанные истории не требуется. Тот же результат даёт создание репозитория на
GitHub **пустым** (без README) и `git init` в папке выгрузки.

### Компактный режим

Полная лента занимает ~320 px и на узком окне Конфигуратора накрывает
собственные кнопки тулбара 1С. Если ширина клиентской области рамки становится
меньше `compactwidth` из ini, панель сворачивается в одну ячейку с многоточием;
щелчок по ней открывает popup-меню со всеми действиями (разделы:
выгрузка/репозиторий, синхронизация, списки, настройки), включая клонирование.
При расширении окна лента возвращается сама — режим пересчитывается по таймеру
500 мс и при изменении размера рамки. Порог `0` отключает компактный режим.

## 3. Оформление окон

Все окна, которые открывает панель — настройки, история, списки веток/stash/тегов
и рабочей копии, ввод комментария к коммиту — оформлены в палитре дизайнера 1С,
снятой с живого конфигуратора: кремовый фон `#F5F2DD`, рамки полей `#B0A68E`,
белые области ввода, плоские кнопки с бежевой подсветкой при наведении и нажатии,
выделение строк списка синим `#316AC5` (серым, когда фокус ушёл со списка), шрифт
Tahoma 8 pt, масштабируемый по DPI. Общие помощники — `UiFrame`,
`UiDrawButton`, `ThemedButton` (подсветка ownerdraw-кнопок) и `UiDrawOwnerButton`
в `gitbar.cpp`. Системные MessageBox'и, как и в самой 1С, остаются штатными.

## 4. Настройки

`%APPDATA%\v8inject\gitbar.ini`, секция `[git]`:

```ini
[git]
gitpath=C:\Program Files\Git\cmd\git.exe   ; путь к git.exe (по умолчанию — из PATH)
dumpdir=E:\dump\config                     ; папка выгрузки = корень репозитория
commitmsg=                                 ; комментарий по умолчанию (пусто = дата-штамп)
remote=git@github.com:user/repo.git        ; origin для git init (необязательно)
compactwidth=900                           ; ширина окна (px), ниже которой панель сворачивается в одну кнопку; 0 = не сворачивать
```

Тот же ini пишет диалог настроек GUI и читает payload. Диалог настроек панели —
полностью рисованный (свой карет, Ctrl+V из клипборда), класс `V8iGitBarSettings`.

## 5. Механика запуска git

`RunGit` (`gitbar.cpp:115-178`):

- командная строка `"gitpath" "arg"...`; anonymous pipe с наследуемым концом
  записи (`STARTF_USESTDHANDLES`: stdout и stderr → одна труба),
  `CREATE_NO_WINDOW`;
- неблокирующее чтение `PeekNamedPipe` + `WaitForSingleObject(50 мс)`;
  таймаут **120 с** — зависший git (например, ждущий учётные данные в
  консоли) снимается `TerminateProcess` с пометкой `<timeout>`;
- вывод конвертируется из UTF-8; длинный вывод для тултипов обжимается
  до 160 символов.

**Комментарий к коммиту** передаётся через файл `%TEMP%\v8i_commitmsg.txt`
(UTF-8 без BOM, `git commit -F`), потому что argv-кавычки для кириллического
многострочного текста ненадёжны; фолбэк — `-m`, если файл не записался.

## 6. Окно истории

`ShowGitLog` (класс `V8iGitLog`, 960×700, минимум 640×460), три зоны:

- **список коммитов** (~48% высоты): колонки Граф / Коммит / Автор / Дата.
  Строка коммита = моноширинный хеш (Consolas), бейджи веток/тегов и
  комментарий. Граф строится из
  `git log --decorate=full -n 300 --date=short
  --pretty=format:%x1f%H%x1f%h%x1f%an <%ae>%x1f%ad%x1f%d%x1f%s%x1f%P`
  (поля разделены 0x1F): каждая линия ждёт один коммит, первый родитель
  сохраняет колонку коммита, дополнительные родители открывают линии
  справа; слияния и проходящие линии рисуются кубическими кривыми,
  коммит — точкой с ореолом. Лишние бейджи сворачиваются в «+N»;
- **карточка выбранного коммита**: комментарий, бейджи, автор, дата, хеш;
- **панель патча**: `git show --stat --patch --no-color` — номера строк в
  две колонки, знаки +/-, полосы заголовков файлов и hunks, пословная
  подсветка изменённых слов (LCS по токенам пары −/+ строк).

Стиль — общая палитра платформы из §3 (`kDlg*` в `gitbar.cpp`): кремовый
хром `#FCFAEB`, белые строки списка с лёгким чередованием `#F8F6EC`,
светло-голубое выделение `#9ED8EB`, ржавые подписи колонок `#9E522A`,
белое поле диффа с бежевыми полосами заголовков `#D7D3BD`; шрифты
Tahoma 8 / Consolas 9; заголовок окна — общая серая полоса с крестиком.

Навигация: ↑↓ / PageUp / PageDown / Home / End / Enter / Esc; колесо
прокручивает список или дифф; оверлейные скроллбары тянутся мышью.
Окно растягивается.

## 7. Геометрия и отрисовка

- ячейка 24×24, панель 13 ячеек (12 действий + многоточие), 316×24
  (`kCell/kCells/kBarW/kBarH`);
- фон RGB(238,234,222), рамка RGB(176,166,142), подсветка hover/press;
- иконки — 16×16 premultiplied BGRA из `src/payload/icons.h`
  (сгенерирован `tools/gen_icons.py` из PNG, декодер на чистом Python —
  без PIL), рисуются через `AlphaBlend` (msimg32);
- происхождение каждой из 12 иконок зафиксировано в
  `src/payload/icons/SOURCE.json` (файл ресурса 1С + смещение);
- подсказки: 12 per-cell инструментов `TTF_SUBCLASS` (показываются при
  наведении, ширина до 360 px) и отдельный `TTF_TRACK`-инструмент для
  статусов действий; он же снимается таймером 2 через 3 секунды.

## 8. Автоматическая проверка

`tools/check_gitbar.sh [8.3|8.5] [--keep]` — E2E-тест (локально, нужна
установленная платформа):

1. закрыть тестовые `1cv8`;
2. запустить Конфигуратор (`DESIGNER /F <база> /DisableStartupDialogs…`);
   8.3 → `8.3.27.1989` x86 + база `awa_empty`; 8.5 → `8.5.1.1529` x64 + база
   `awa_empty_851`;
3. внедрить: `v8inject gitbar 1cv8.exe --pid <pid>`; в ответе должно быть
   `"status":"ok"`, `"visible":true`;
4. через PowerShell/EnumWindows найти окно класса `V8iGitBar` по PID,
   проверить видимость и ненулевой размер;
5. уборка; exit 0/1.

Скрипт уже поймал реальные регрессии (падение из-за CBT-хука) — прогонять
перед каждым коммитом, затрагивающим payload или панель.
