# v8inject

Инжектор и точка расширения для процессов 1С:Предприятие.

Подробная документация: [docs/](docs/) —
[архитектура](docs/ARCHITECTURE.md),
[справочник команд](docs/CLI.md),
[GitBar](docs/GITBAR.md),
[ревизия проекта](docs/AUDIT.md),
[инвентарь 8.5](docs/RECON-85.md),
[план исследования 8.5](docs/plan_inj_ext.md).

## Что делает

- находит процесс `1cv8.exe` / `1cv8c.exe` / `1cv8s.exe` по имени
- внедряет payload-DLL в целевой процесс (`LoadLibrary` + `CreateRemoteThread`)
- внутри процесса читает PE-модули через PEB и разбирает COM type library
  (`ITypeInfo`): `memid`, `oVft`, `cParams`, типы параметров, имена методов
- отдаёт отчёт наружу в JSON через разделяемую память

## Сборка

Требуется Windows и Visual Studio 2022 (или Build Tools) с C++ workload.

```bat
cmake -S . -B build\x86 -G "Visual Studio 17 2022" -A Win32
cmake --build build\x86 --config Release

cmake -S . -B build\x64 -G "Visual Studio 17 2022" -A x64
cmake --build build\x64 --config Release
```

Результат:

```
build\x86\bin\x86\v8inject.exe
build\x86\bin\x86\v8inject-gui.exe
build\x86\bin\x86\v8inject-agent.exe
build\x86\bin\x86\v8i_payload.dll
build\x64\bin\x64\v8inject.exe
build\x64\bin\x64\v8inject-gui.exe
build\x64\bin\x64\v8inject-agent.exe
build\x64\bin\x64\v8i_payload.dll
```

Payload и хост должны совпадать по разрядности с целевым процессом.

## Использование

```bat
v8inject --help
v8inject modules 1cv8.exe
v8inject inject 1cv8.exe --dll bin\x64\v8i_payload.dll

# любой команде можно указать --pid <n>, если процессов с таким именем несколько
# (две открытые 1С, например):
v8inject hook 1cv8.exe core83.dll!findMethod --pid 12345

# запуск 1С с немедленным внедрением payload (до создания главного окна —
# так payload успевает подписаться на события 8.5):
v8inject launch 'C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe' DESIGNER /F E:\bases\test

# диалог с загруженным payload — команды идут вторым аргументом после exe:
v8inject probe   1cv8.exe                  # версия payload, проверка связи
v8inject objects 1cv8.exe                  # окна/объекты, найденные по vtable
v8inject pe      1cv8.exe [module]         # PE-заголовок модуля
v8inject peek    1cv8.exe <addr> [len]     # дамп памяти по адресу
v8inject find    1cv8.exe <pattern> [--wide] [--max N]
v8inject scan    1cv8.exe <iunknown> [--module 1cv8.exe]   # разбор COM-интерфейса

# реверс-инжиниринг (доступны и в GUI через строку команды):
v8inject disasm 1cv8.exe [<addr>] [--module m]        # дизассемблер Capstone
v8inject around 1cv8.exe <addr> [--count N]           # инструкции вокруг адреса
v8inject xref   1cv8.exe <addr|imp-name> [--from A --to B] [--count N]
v8inject imports 1cv8.exe <module> [filter]           # импорты модуля
v8inject memmap 1cv8.exe [--count N]                  # карта приватной памяти
v8inject heapobjects 1cv8.exe [--module m] [--count N]   # живые объекты кучи
v8inject findvalue 1cv8.exe <hex> [--count N] [--module m] # все 4-байтные вхождения
v8inject byhwnd 1cv8.exe <hwnd> [--offset 0x200]       # объект, владеющий окном

# ранняя подписка на 8.5: глобальный WH_CBT с hMod=payload — Windows сама
# загрузит payload в 1С при создании первого окна (хост держит хук N секунд):
v8inject hookcbt [секунд]

# триггер на выгрузку конфигурации в файлы для git-конвейера:
v8inject watch 1cv8.exe --dump-dir E:\dump\config --run "git add -A && git commit -m auto"

# слой расширения: inline-хуки и трассировка вызовов
v8inject attach 1cv8.exe                               # интерактивная сессия
#   в сессии одной строкой на команду: hook <addr|module!Export|module+0xRVA>
#   [--name text], hooks, unhook <id|all>, trace [--count N] [--since N] [--clear],
#   sleep <ms> (выполняется хостом между командами), exit
v8inject hook   1cv8.exe <addr|module!Export|module+0xRVA> [--name text]
v8inject hooks   1cv8.exe
v8inject unhook  1cv8.exe <id|all>
v8inject trace   1cv8.exe [--count N] [--since N] [--clear]
v8inject log [--clear]                                # лог хоста
```

Цель для `hook` задаётся адресом (`0x619E9F70`), экспортом модуля
(`core83.dll!findMethod`) или RVA (`core83.dll+0x39F70`). Имя экспорта
сначала ищется точно, затем без учёта регистра, затем как подстрока — имена
движка манглированы (`?findMethod@COMContext@core@@UAGH...`), поэтому подстрока
и есть рабочий способ. Если подстрока подходит к нескольким экспортам, хук не
ставится: в ответе перечислены кандидаты с RVA, чтобы выбрать один.

`v8inject-gui.exe` — оконная версия: список процессов с фильтром,
выбор payload-DLL по разрядности цели, строка команды и живой лог.
Окно запускается с правами администратора: если 1С стартовала с повышенными
правами, подключение без них падает с `ACCESS_DENIED` (win32=5).

`v8inject-agent.exe` — трей-агент: следит за запуском 1С, внедряет payload
сам (один раз на процесс), по настройке сразу показывает GitBar; может
стоять в автозапуске. Настройки — `%APPDATA%\v8inject\agent.ini`.

## GitBar — git-панель в конфигураторе

Панель живёт **внутри процесса 1С**: это дочернее окно окна конфигуратора,
пристыкованное справа в ряду тулбара, поэтому выглядит как штатный тулбар —
включая иконки: все 12 взяты из ресурсов самой платформы (`core83_root.res`,
`mngcore_root.res`, `core85_root.res` и др.), а не нарисованы заново.
При наведении на кнопку показывается подсказка с действием и git-командой.
Подробно — [docs/GITBAR.md](docs/GITBAR.md).

```bat
v8inject gitbar 1cv8.exe --pid 12345   # показать (payload остаётся в процессе)
v8inject gitbar hide 1cv8.exe --pid 12345
```

То же из `v8inject-gui.exe`: выбрали процесс → «GitBar: показать».
Или автоматически: `v8inject-agent.exe` показывает панель при старте 1С.

Двенадцать кнопок слева направо:

| Кнопка | Что делает |
|---|---|
| дискета | выгрузка конфигурации в файлы — штатная команда дизайнера (45) |
| лист с плюсом | `git init` в папке выгрузки + `remote add origin` из настроек |
| стопка с галочкой | `git add -A` и коммит; комментарий спрашивается каждый раз |
| стрелка вверх | `git push`; грязное дерево предлагает закоммитить, при отсутствии upstream — `push -u origin HEAD` |
| шестерёнка | настройки |
| часы с карандашом | история: граф коммитов + патч выбранного коммита |
| стрелка вниз / круговые стрелки | `git pull --no-edit` / `git fetch --all --prune` |
| граф веток / стопка листов / звезда | списки веток, stash и тегов с действиями (checkout, pop, push и т.д.) |
| документ с галочкой | рабочая копия: индексировать, снять, отменить, коммит, amend |

Многоточие в конце ленты открывает popup-меню со всеми действиями. Там же —
«Выгрузить расширение в файлы (команда 205)»: выгрузка выбранного расширения
в `dumpdir` для отдельного git-репозитория. Команда контекстная, поэтому перед
запуском откройте «Расширения конфигурации» и выберите расширение — если активным
окажется другое окно, панель отменит диалог выгрузки основной конфигурации и
покажет предупреждение.

Настройки пишутся в `%APPDATA%\v8inject\gitbar.ini` (секция `[git]`):

```ini
[git]
gitpath=C:\Program Files\Git\cmd\git.exe   ; путь к git.exe
dumpdir=E:\dump\config                     ; папка выгрузки = корень репозитория
commitmsg=                                 ; комментарий по умолчанию (пусто = подставляется дата)
remote=git@github.com:user/repo.git        ; origin для git init (необязательно)
```

Комментарий к коммиту передаётся через файл в UTF-8, поэтому кириллица и
многострочный текст не ломаются; git, ждущий ввод учётных данных, снимается
по таймауту, а не вешает панель.

## Команды дизайнера

`cmd <num> [sub]` вызывает штатную команду конфигуратора (`ICommandReceiver::transmitCommand`)
на UI-потоке — так работает кнопка выгрузки и любые другие действия меню.
На 8.3 это команда payload `cmd` (пока только внутри сессии `attach`),
на 8.5 — `cmd85` (доступна и отдельной командой CLI):

```bat
v8inject attach 1cv8.exe
cmd 2        # открыть конфигурацию (8.3)
cmd 45       # выгрузить конфигурацию в файлы (8.3)
exit

v8inject cmd85 1cv8.exe 45     # выгрузка на 8.5
v8inject cmdinfo 1cv8.exe      # диагностика цепочки команд
v8inject frames  1cv8.exe      # что прислал eventCreateFrame (8.5)
```

Калибровка (8.3.27.1989): x86 — `recv = core − 0x10`, `transmitCommand = frame.dll + 0x8980A0`;
x64 — `recv = core − 0x20`, `transmitCommand = frame.dll + 0x921730`.

## Хуки

`hook` ставит inline-детур на начало функции: первые байты пролога заменяются
переходом на заглушку, заглушка передаёт регистры общему thunk'у, тот пишет
запись в кольцевой буфер и уходит в трамплин — копию перезаписанных инструкций
плюс переход назад в функцию. Функция продолжает работать, а вызовы видны
снаружи.

Что поддерживается:

- x86 и x64; патч — 5-байтный `jmp rel32` на обеих архитектурах, поэтому блок
  хука всегда выделяется в пределах ±2 ГБ от цели, а пролог перезаписывается
  минимально (целыми инструкциями, длины берутся из Capstone);
- RIP/EIP-относительные операнды переносятся: дисплейсмент правится на разницу
  адресов;
- относительные переходы и вызовы в прологе переносятся: `rel32` правится на
  месте, `rel8` (`jmp`/`jcc`) переписывается в 32-битную форму, цель внутри
  перезаписываемого окна переназначается на копию инструкции в трамплине;
- `loop`/`jecxz`/`jrcxz` отклоняются: у них нет формы с 32-битным смещением;
- пролог, который заканчивается `ret` или переходом *за пределы* пролога
  раньше, чем набралось 5 байт, отклоняется — байты за ним могут принадлежать
  другой функции;
- запись вызова: id хука, tid, тик, адрес возврата и первые четыре аргумента
  (`rcx/rdx/r8/r9` на x64, первые четыре стека на x86). SSE-аргументы не
  перехватываются;
- снятие хука восстанавливает оригинальные байты; блок с трамплином не
  освобождается — поток, уже находящийся в трамплине, иначе прыгнул бы в
  освобождённую память.

Хуки живут столько же, сколько сессия: одиночная команда (`v8inject hook ...`)
снимает их при закрытии сессии, поэтому для наблюдения за живым процессом
используется `attach`. Падение внутри хукнутой функции попадает в
`v8inject.log` (векторный обработчик пишет регистры и адрес исключения).

Вывод payload — JSON (UTF-8). Команды принимают адреса в виде `0x...`,
числа — шестнадцатеричные или десятичные.

## Структура

```
include/v8inject/   публичные заголовки
src/common/         PE-разбор, ITypeInfo, JSON-отчёт, лог
src/payload/        DLL, которая грузится В целевой процесс
src/host/           внедрение (снаружи)
src/cli/            консольный интерфейс
src/gui/            оконная версия v8inject-gui
src/agent/          v8inject-agent — трей, авто-внедрение при старте 1С
tests/              smoke-тест хуков
tools/              E2E-проверки, recon-скрипты, генератор иконок
```

## CI

GitHub Actions собирает обе разрядности на `windows-2022`,
прогоняет smoke-тест и складывает артефакты. Пуш тега `v*` дополнительно
публикует GitHub Release с zip-архивами x86/x64 (только v8inject.exe,
v8inject-gui.exe, v8inject-agent.exe и v8i_payload.dll). Заметки берутся из
файла `RELEASE.md` в корне тега, если он там есть, иначе генерируются из
коммитов.

## Отказ от ответственности

Проект не связан с фирмой «1С». Внедрение кода в чужой процесс может
нарушать лицензионное соглашение приложения и привести к потере данных.
Использование — на свой риск, автор ответственности не несёт.
